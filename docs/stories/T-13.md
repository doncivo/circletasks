# T-13 — J'annule ma dernière action

Module : M1 Tâches · Ordre de construction : 1 (Socle) · Agent : **tasks-planning** (composant Toast : ui-design-system) · Statut : à faire

## Rappel PRD (section 4, M1)

| ID | User story | Critères d'acceptation |
| --- | --- | --- |
| T-13 | J'annule ma dernière action | Terminer, reporter, déplacer, dupliquer, supprimer : message « Annuler » affiché 5 s ; Ctrl+Z sur PC ; 20 dernières actions annulables dans la session |

Contrat : ADR 0005 (`UndoStack`, `UNDO_TOAST_MS`, commande 'stale').

## Références visuelles

- Gestes.html : bandeau bas d'écran role="status", fond #2E2150, texte blanc « « Courses » reportée à demain », bouton « Annuler » fond #F2A7A0, au-dessus de l'interrupteur d'édition et du bouton +.

## Critères testables

1. **Étant donné** une action terminer, reporter, déplacer (date, glisser S-02, ordre A-02), dupliquer ou supprimer, **alors** un message décrivant l'action (« « <titre> » terminée / reportée à demain / déplacée au jeu. 24 / dupliquée / supprimée ») et un bouton « Annuler » s'affichent pendant 5 s.
2. **Quand** je touche « Annuler » pendant les 5 s, **alors** l'état antérieur exact est rétabli (date, heure, statut, ordre, présence) et le message disparaît.
3. **Étant donné** deux actions successives en moins de 5 s, **alors** le message affiche la dernière et son minuteur repart à 5 s.
4. **Étant donné** le PC, hors champ de saisie, **quand** j'appuie sur Ctrl+Z, **alors** la dernière action non annulée est annulée, même après disparition du message ; dans un champ de saisie, Ctrl+Z reste l'annulation de texte.
5. **Étant donné** 21 actions annulables, **alors** seules les 20 dernières le sont ; la 21ᵉ annulation par Ctrl+Z n'a aucun effet.
6. **Étant donné** une action par lot (A-05, 3 tâches), **alors** une seule annulation rétablit les 3 tâches ; message au pluriel (« 3 tâches reportées »).
7. **Étant donné** une tâche modifiée depuis l'action (autre action ou synchro), **quand** j'annule l'action ancienne, **alors** rien n'est écrit et le message « Action impossible à annuler : la tâche a changé » s'affiche (résultat 'stale').
8. **Étant donné** un redémarrage de l'app, **alors** la pile est vide.
9. **Alors** le message est annoncé par les lecteurs d'écran (role="status"), le bouton « Annuler » est atteignable au clavier, et le délai de 5 s est suspendu tant que le message a le focus ou est survolé.
10. Les actions non listées (créer, modifier le titre, la note) ne produisent pas de message « Annuler ».

## Hors de cette story

- Chaque action (T-04, T-05, T-08, T-12, S-02, A-02, A-05) déclare sa commande ; T-13 livre le mécanisme commun, le message et Ctrl+Z, et vérifie leur intégration.
- C-05 (effacer les cochés, ordre 2) réutilisera le mécanisme.

## Ordre des sous-tâches

1. Vérifier l'implémentation `UndoStack` (ADR 0005) : 20 commandes, 'stale', sérialisation ; tests.
2. ui-design-system : composant `Toast` avec action, pause au focus/survol, respect de prefers-reduced-motion.
3. Raccourci `app.undo` (Ctrl+Z, hors champ) ; libellés i18n avec pluriel (`Intl.PluralRules`, ADR 0004 point 4).
4. Intégration avec les actions déjà livrées ; e2e « terminer, reporter, supprimer puis 3 × Ctrl+Z ».
5. qa-test, code-reviewer, vérification product-owner.

## Écarts

- Critère 9 (pause du délai au focus) : ajout d'accessibilité (WCAG 2.2.1), non écrit dans le PRD ; à valider par accessibility-i18n.
