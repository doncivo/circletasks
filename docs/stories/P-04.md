# P-04 — Je sauvegarde et restaure mes données

## Références visuelles

- Reglages.html, section « DONNÉES ET SÉCURITÉ » : « Sauvegarde automatique » avec sous-ligne « Aujourd'hui 03:00 · 14 versions » (13 px, #5E557A) et bouton « Restaurer » (lien). Aucune maquette de la liste des versions ni de la confirmation : feuille / fenêtre dans le style des écrans de Réglages.

## Critères testables

Existant à réutiliser : `src-tauri/src/backup.rs` (dossier `backups/`, `VACUUM INTO`, préfixe `circletasks-pre-migration-`, 5 versions, nom `circletasks-daily-AAAAMMJJ.db` réservé à cette story).

1. **Étant donné** que l'app tourne ou démarre et qu'aucune sauvegarde du jour n'existe, **alors** une sauvegarde `circletasks-daily-AAAAMMJJ.db` est créée (point de contrôle WAL puis `VACUUM INTO`, base jamais verrouillée plus de 2 s), sans bloquer l'interface ; à partir de minuit, la première occasion (ouverture, retour de veille, retour au premier plan sur iPhone) en crée une.
2. **Alors** seules les 14 sauvegardes quotidiennes les plus récentes sont gardées ; les sauvegardes avant migration (5) sont comptées à part et jamais supprimées par cette purge.
3. **Alors** la ligne de Réglages affiche l'heure réelle de la dernière sauvegarde et le nombre de versions (« Aujourd'hui 03:12 · 14 versions », « Hier 21:40 · 6 versions », « Aucune sauvegarde ») ; une erreur de sauvegarde s'affiche en rouge (« Dernière sauvegarde échouée ») et est consignée.
4. **Quand** je touche « Restaurer », **alors** une feuille liste les versions (date, heure, taille, nombre de tâches si lisible), les plus récentes d'abord, avec les sauvegardes avant migration marquées « Avant mise à jour » ; un bouton « Sauvegarder maintenant » remplace la version du jour.
5. **Quand** je choisis une version, **alors** une confirmation explique « Les données actuelles seront remplacées par celles du 3 oct. à 03:12. Une copie de l'état actuel est faite avant. » avec « Restaurer » (destructif, rouge #9E3F33) et « Annuler » ; un seul clic de confirmation suffit (restauration en 1 clic).
6. **Alors** la restauration : copie de sécurité de l'état actuel (`circletasks-pre-restore-AAAAMMJJTHHMMSSZ.db`, 3 gardées), vérification de la version choisie (`PRAGMA integrity_check`, `schema_version` ≤ celle de l'app), remplacement atomique du fichier, puis redémarrage automatique de l'app ; l'app rouvre sur les données restaurées.
7. **Étant donné** une version plus ancienne, **alors** les migrations se rejouent à l'ouverture (avec la sauvegarde avant migration de D-03) ; **étant donné** une version plus récente que l'app ou un fichier corrompu, **alors** la restauration est refusée avec un message et rien n'est modifié.
8. **Étant donné** que la restauration échoue à mi-chemin (simulé), **alors** l'ancien fichier est rétabli, l'app démarre sur l'état d'avant.
9. **Alors** les sauvegardes sont locales et non chiffrées (contenu identique à la base) : le dossier `backups/` n'est jamais synchronisé ; l'aide indique l'emplacement ; sur PC, « Afficher dans le dossier ».
10. **Alors** les tests Rust couvrent nommage, purge (14 / 5), restauration atomique et échec simulé ; les tests TypeScript, le calcul « une sauvegarde par jour » avec horloge injectable.
11. **iPhone** : mêmes comportements (le code Rust est partagé, dossier de l'app) ; sauvegarde au premier plan, pas en arrière-plan.
12. Accessibilité : la confirmation reçoit le focus sur « Annuler » ; le redémarrage est annoncé (« Restauration terminée, redémarrage »).

## Hors de cette story

- Interaction avec la synchro iCloud (ordre 4) : après une restauration, les journaux déjà publiés par cet appareil et les autres appareils peuvent faire réapparaître des données ; à traiter avec Y-02, Y-09 (inscrit aux dettes). Export de la base hors de l'appareil. Chiffrement des sauvegardes. Restauration partielle (une tâche).

## Décisions (validation automatique)

- D1 — « 03:00 » de la maquette est un exemple de dernière sauvegarde, pas une heure planifiée : un PC éteint la nuit sauvegarde à la première ouverture du jour.
- D2 — « Restauration en 1 clic » : un choix dans la liste puis une confirmation ; pas de restauration sans confirmation (action destructive).
- D3 — Copie de sécurité avant restauration (3 gardées) : jamais de perte irréversible.
- D4 — Redémarrage via le plugin process après remplacement (la connexion SQLite unique est fermée avant).
- D5 — Un bouton « Sauvegarder maintenant » est ajouté dans la liste des versions (non dessiné) : utile avant une manipulation risquée.
