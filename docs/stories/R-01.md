# R-01 — Je crée une routine avec icône et fréquence

Module : M4 Routines · Ordre de construction : 1 (Socle) · Agent : **routines** · Statut : à faire
Dépend de : socle T-01 (tables `routine`, `routine_log`, espaces semés), ADR 0004.

## Rappel PRD (section 4, M4)

| ID | User story | Critères d'acceptation |
| --- | --- | --- |
| R-01 | Je crée une routine avec icône et fréquence | Choix : tous les jours, jours précis, X fois par semaine ; tous les N jours ou N semaines (R-07) |

Section 5 : carte = icône, titre, 7 ronds L M M J V S D, compteur « 1/7 », heure, bouton « Éditer » ; phrase d'aide sous la liste. Section 6 : `schedule_type` daily / weekdays / x_per_week / every_n_days / every_n_weeks ; occurrences calculées, jamais stockées.

## Références visuelles

- Routines.html (iPhone) : titre « Routines », pastilles Pro / Perso / Tout, cartes, phrase « Gérez vos routines ici et cochez-les dans la liste du jour. », bouton « Rapport du mois », bouton rond « + » (aria-label « Ajouter une routine ») qui ouvre la feuille Ajout sur l'onglet « Routine ».
- PC-Routines.html : cartes en grille de 2 colonnes, pied « Cochez les routines dans la liste du jour · Ctrl N nouvelle routine », bouton rond « Ajouter ».
- ModifierRoutine.html : formulaire de référence (nom, Icône / Emoji, rangée d'icônes, « Fréquence : Jours choisis » + 7 ronds, heure et rappel, Espace Pro / Perso, « Enregistrer »).

## Critères testables

1. **Étant donné** l'onglet Routines (iPhone), **quand** je touche « + », **alors** la feuille « Nouvelle tâche » s'ouvre sur l'onglet « Routine » avec le formulaire de ModifierRoutine.html (titre « Nouvelle routine », sans « Archiver », sans pause ni série).
2. **Étant donné** l'onglet Routines (PC), **quand** je clique « + » ou j'appuie sur Ctrl+N, **alors** le formulaire de création s'ouvre dans le panneau de droite, champ nom focalisé.
3. **Étant donné** le formulaire, **quand** le nom est vide (après trim) ou la fréquence « Jours choisis » n'a aucun jour coché, **alors** « Enregistrer » est grisé (disabled, aria-disabled). Nom : 1 à 200 caractères, comme T-01.
4. **Étant donné** le sélecteur « Fréquence », **alors** il propose : « Tous les jours », « Jours choisis », « X fois par semaine », « Tous les N jours » (bascule jours / semaines, voir R-07).
5. **Étant donné** « X fois par semaine », **alors** un compteur − / + règle X de 1 à 7 ; aucun jour n'est choisi.
6. **Étant donné** « Icône » ou « Emoji », **quand** je choisis une icône Lucide ou un emoji, **alors** elle est enregistrée dans le champ unique `icon` (`lucide:nom` / `emoji:…`) et affichée sur la carte et dans la liste du jour, à droite du titre. L'icône est facultative.
7. **Étant donné** une routine enregistrée, **alors** sa carte apparaît dans l'onglet Routines avec icône, titre, ronds L à D (jours non prévus en pointillés), compteur « faits / prévus » de la semaine en cours (lundi → dimanche) et ligne « heure · espace » (ex. « 07:30 · Perso », « 18:00 · lun., mer., ven. »).
8. Compteur : « Tous les jours » → dénominateur 7 ; « Jours choisis » → nombre de jours choisis ; « X fois par semaine » → X ; « Tous les N jours / semaines » → occurrences prévues dans la semaine.
9. **Étant donné** une routine créée aujourd'hui, **alors** `startDate` = aujourd'hui (date locale), sauf choix explicite pour R-07 ; aucun jour antérieur n'est compté comme prévu.
10. **Étant donné** le filtre d'espace, **alors** l'espace proposé suit la règle de T-01 (filtre Pro / Perso, ou Pro en « Tout ») ; l'onglet Routines n'affiche que les routines de l'espace filtré.
11. **Étant donné** une routine prévue aujourd'hui, **alors** elle apparaît dans la liste Aujourd'hui avec la mention « Routine » et son icône (sauf si A-03 la masque).
12. Persistance : redémarrage → routine présente. Libellés dans src/i18n.
13. **Étant donné** une routine « 3 fois par semaine » validée lundi et mardi, **alors** elle apparaît dans Aujourd'hui le mercredi (non cochée) ; **quand** je la valide mercredi (3/3), **alors** elle n'apparaît plus dans Aujourd'hui ni dans la Semaine du jeudi au dimanche, et réapparaît le lundi suivant (QB-01). Le jour où le quota est atteint, la routine validée reste affichée barrée parmi les terminés.

## Hors de cette story

- Heure et rappel : R-02 (le champ est présent mais traité là). Validation : R-03. Série : R-04. Pause / archivage : R-05. Rapport : R-06. Paramètres N et date de départ : R-07.
- Vue compacte de l'onglet (A-06), masquage dans la liste (A-03).

## Ordre des sous-tâches (routines)

1. domain-logic : `validateRoutine` (invariants de `Routine`), `isPlannedOn(routine, date)` pour daily / weekdays, `weekCounter(routine, logs, weekStart)` ; tests Vitest.
2. data-model : `RoutineRepository.create / listBySpace` (si absent).
3. Store `routines` + cas d'usage `createRoutine`.
4. UI : formulaire partagé création / modification (iPhone feuille, PC panneau), cartes, onglet ; i18n.
5. Intégration liste du jour (lecture seule ici).
6. Playwright PC + mise en page 440 × 956 ; qa-test, code-reviewer.

## Écarts et points à arbitrer

- La feuille Ajout, onglet « Routine », n'est pas dessinée : on réutilise le formulaire de ModifierRoutine.html.
- Le formulaire PC n'est pas dessiné : il s'affiche dans le panneau de droite (bouton « Modifier » de PC-Routines.html).
- « X fois par semaine » : affichage dans Aujourd'hui tranché (QB-01, voir ci-dessous).

## Décisions d'Ali (2026-10-02)

- **QB-01** : une routine « X fois par semaine » apparaît dans Aujourd'hui chaque jour de la semaine (lundi → dimanche) tant que les X validations ne sont pas atteintes, puis plus du tout jusqu'au lundi suivant. Le quota n'est pas dépassable. Critère 13 ajouté.
