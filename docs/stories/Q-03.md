## Critères testables

1. **Étant donné** le champ d'ajout PC (Aujourd'hui, feuille Ajout, mini-fenêtre Q-01), **alors** un bouton micro (icône Lucide au trait, 44 × 44) est présent à droite du champ, nommé « Dicter ».
2. **PC, quand** je l'active, **alors** le champ prend le focus et une aide discrète indique « Appuyez sur Win + H pour dicter, parlez, puis relisez avant d'ajouter » ; le texte dicté par Windows arrive dans le champ comme une saisie ordinaire.
3. **Étant donné** du texte dicté (« appeler le notaire demain dix heures »), **alors** il n'est jamais envoyé seul : la tâche n'est créée qu'à Entrée ou « Ajouter » (relecture = le champ + la pastille d'aperçu de Q-02 / Q-06) ; une dictée n'envoie rien automatiquement.
4. **Alors** la dictée passe par les mêmes analyses que la saisie (Q-02 : « demain dix heures » n'est pas reconnu, mais « demain 10 h » l'est ; les nombres écrits en lettres sont convertis pour les heures courantes : « dix heures », « neuf heures trente », « midi »).
5. **iPhone** : le micro du clavier iOS (dictée native) fonctionne dans le champ sans autre code ; le bouton micro propre à l'app n'est affiché que si `speech.isAvailable()` renvoie vrai (à l'ordre 3, jamais : le contrat `SpeechRecognizer` est défini dans `src/platform/speech` avec une implémentation vide et un faux de test).
6. **Étant donné** le faux `SpeechRecognizer` renvoyant « Appeler le plombier demain 9 h », **quand** je touche le micro, **alors** une feuille « Je vous écoute » avec bouton « Terminer » s'affiche, puis le texte arrive dans le champ pour relecture (pas de création) ; refus de permission : message « Autorisez le micro dans les Réglages de l'iPhone » sans planter.
7. **Alors** aucun enregistrement audio n'est conservé ni envoyé par l'app (pas de service réseau tiers, pas de fichier).
8. Accessibilité : l'aide est lue (`aria-describedby`) ; le bouton micro est atteignable au clavier.

## Hors de cette story

- Plugin Swift Speech (reconnaissance fr-FR sur l'iPhone, permissions micro et reconnaissance vocale) : ordre 5 (I-05 pour le moment de la demande). Moteur de transcription embarqué (hors périmètre : taille, vie privée). Commandes vocales, Siri (hors périmètre PRD).

## Décisions (validation automatique)

- D1 — Sur PC, pas de moteur propre à l'app : la dictée Windows (Win + H) saisit dans le champ ; l'app apporte l'aide et la relecture. Un envoi programmatique de Win + H (SendInput) est écarté : fragile et dépendant de la langue.
- D2 — L'interface `SpeechRecognizer` (`isAvailable`, `listen({ locale: 'fr-FR' }) → texte`) est livrée maintenant pour que l'ordre 5 branche Speech sans toucher à l'écran.
- D3 — Conversion de nombres en lettres limitée aux heures courantes (« dix heures », « neuf heures trente », « midi », « minuit ») dans `parseQuickInput` ; le reste du titre est inchangé.

## Ordre des sous-tâches

1. platform : contrat `SpeechRecognizer`, implémentation indisponible, faux ; tests.

3. UI : bouton micro, aide PC, feuille d'écoute (visible seulement si disponible) ; i18n.
4. qa-test, code-reviewer. Vérification réelle de la dictée Win + H par Ali.
