# R-07 — Je planifie une routine tous les N jours ou toutes les N semaines

Module : M4 Routines · Ordre de construction : 1 (Socle) · Agent : **routines** · Statut : à faire
Dépend de : R-01.

## Rappel PRD (section 4, M4)

| ID | User story | Critères d'acceptation |
| --- | --- | --- |
| R-07 | Je planifie une routine tous les N jours ou toutes les N semaines | N de 2 à 30 jours ou de 2 à 8 semaines ; date de départ choisie ; compteur et séries calculés sur les jours prévus |

## Références visuelles

- ModifierRoutine-N.html : « Fréquence : Tous les N jours » ; encart « Tous les − 3 + » avec bascule « jours » / « semaines » ; « À partir du Lun. 21 sept. » ; « Prochaines fois : jeu. 24, dim. 27, mer. 30 sept., sam. 3 oct. ».

## Critères testables

1. **Étant donné** « Tous les N jours », **alors** N vaut 2 par défaut ; « − » est inactif à 2 ; « + » est inactif à 30 en jours et à 8 en semaines ; passer de jours à semaines ramène N à 8 s'il dépasse 8.
2. **Étant donné** « À partir du », **quand** je touche la date, **alors** un sélecteur de date s'ouvre ; par défaut, aujourd'hui. Une date passée est acceptée.
3. **Étant donné** N = 3 jours à partir du lun. 21 sept., **alors** l'aperçu affiche « Prochaines fois : jeu. 24, dim. 27, mer. 30 sept., sam. 3 oct. » (4 prochaines dates à partir d'aujourd'hui, dates abrégées en français).
4. **Étant donné** N = 3 jours, **alors** la routine apparaît dans Aujourd'hui et Semaine uniquement aux dates départ + k × 3 (k ≥ 0).
5. **Étant donné** N = 2 semaines à partir du lun. 21 sept., **alors** les ronds L à D s'affichent sous l'encart avec seul « L » coché (jour de la date de départ) et la routine est prévue les lundis 21 sept., 5 oct., 19 oct.… ; **quand** je coche aussi « J », **alors** elle est prévue les lun. 21 et jeu. 24 sept., lun. 5 et jeu. 8 oct.… ; **quand** aucun jour n'est coché, **alors** « Enregistrer » est grisé (QB-04).
6. **Étant donné** une routine tous les N jours, **alors** le compteur de la carte = validations / occurrences prévues dans la semaine courante (ex. « 1/2 »), et les ronds des jours non prévus sont en pointillés.
7. **Étant donné** une occurrence prévue manquée, **alors** la série revient à 0 ; les jours intermédiaires ne la cassent pas (R-04).
8. **Étant donné** que je modifie N ou la date de départ, **alors** les validations passées sont conservées ; seules les occurrences futures changent.
9. Calcul indépendant du fuseau (dates locales), passage à l'heure d'été sans décalage (test 29 mars et 25 oct.).

## Hors de cette story

- Récurrences de tâches (T-09) : distinctes des routines.

## Ordre des sous-tâches (routines)

1. domain-logic : `isPlannedOn` pour every_n_days / every_n_weeks, `nextOccurrences(routine, from, count)` ; tests bornes et DST.
2. UI encart N, bascule, sélecteur de date, aperçu.
3. qa-test, code-reviewer.

## Écarts et points à arbitrer

- Le mode « semaines » n'est pas dessiné (choix des jours de semaine) : tranché (QB-04, voir ci-dessous).

## Décisions d'Ali (2026-10-02)

- **QB-04** : en mode « Toutes les N semaines », les ronds L à D s'affichent, préréglés sur le jour de semaine de la date de départ ; plusieurs jours peuvent être cochés (champ `weekdays` d'every_n_weeks, ADR 0004). Critère 5 ajusté.
