# H-03 — J'exporte mon historique

Module : M11 Statistiques · Ordre de construction : 3 (rang 12) · Agent : **stats-history** (avec desktop-tauri pour l'enregistrement de fichiers) · Statut : en revue
Dépend de : H-01, H-02, F-03. Interface `src/platform` « export et fichiers » (dette de l'ordre 3) créée ici, réutilisée par P-04 et P-07.

## Rappel PRD (section 4, M11 ; section 7)

| ID | User story | Critères d'acceptation |
| --- | --- | --- |
| H-03 | J'exporte mon historique | Export CSV et JSON ; rapport mensuel exporté en PDF ou en image |

Agent stats-history : CSV à séparateur point-virgule, UTF-8 avec BOM pour Excel, et JSON ; rapport en PDF ou PNG.

## Références visuelles

- Aucune maquette d'export. Bouton « Exporter » (icône téléchargement Lucide, pilule 36 px contour #D9D4E4, comme « Reprendre la photo ») à droite des pastilles d'espace de Rapport.html, ouvrant une fenêtre (PC) ou une feuille (iPhone) dans le style des feuilles de l'app.

## Critères testables

1. **Étant donné** le rapport mensuel, **alors** un bouton « Exporter » ouvre « Exporter l'historique » avec : Contenu (« Historique en CSV », « Historique en JSON », « Rapport du mois en PDF », « Rapport du mois en image »), Période (« Tout l'historique » / « Mois affiché », pour CSV et JSON) et rappel du filtre d'espace en vigueur.
2. **CSV** : **quand** j'exporte, **alors** un fichier `circletasks-taches-AAAA-MM-JJ.csv` est proposé à l'enregistrement : séparateur « ; », UTF-8 avec BOM, première ligne d'en-têtes `titre;date;heure;espace;projet;note;statut;termine_le;objectif;repetition` (les six premières = format d'import P-07), une ligne par tâche, dates `AAAA-MM-JJ`, heures `HH:MM`, guillemets doublés, retours à la ligne des notes conservés entre guillemets.
3. **JSON** : **alors** un fichier `circletasks-historique-AAAA-MM-JJ.json` contient `{ schema_version, exported_at, filter, tasks, routines (avec validations et pauses), focus_sessions, goals }` ; identifiants stables ; heures en UTC et date locale ; aucun jeton ni réglage.
4. **Filtre** : **étant donné** Pro, **alors** seuls les éléments Pro sont exportés (routines, sessions et objectifs via leur espace) ; le nom du fichier reçoit le suffixe `-pro`.
5. **PDF** : **alors** `circletasks-rapport-2026-09.pdf` (A4 portrait, une page) reprend le rapport du mois affiché : titre, tuiles, graphique, carte de chaleur et taux des routines, aux couleurs et polices de la maquette.
6. **Image** : **alors** `circletasks-rapport-2026-09.png` (1 080 px de large) reprend le même rendu.
7. **Quand** j'enregistre, **alors** une boîte « Enregistrer sous » système s'ouvre (PC) ; annuler n'affiche pas d'erreur ; l'app n'a accès qu'au fichier choisi ; un message « Historique exporté » apparaît, avec « Afficher dans le dossier » sur PC.
8. **Étant donné** un historique de 3 ans (5 000 tâches), **alors** l'export CSV ou JSON prend moins de 2 s sans figer l'interface (écriture par blocs, indicateur).
9. **Étant donné** que l'export échoue (disque plein, droits), **alors** un message clair s'affiche, aucun fichier partiel n'est laissé.
10. **iPhone** : la fenêtre et les contenus sont identiques, mais l'enregistrement dépend du plugin Fichiers de l'ordre 5 ; à l'ordre 3 le bouton n'apparaît que si `files.canSave()` est vrai (jamais sur iPhone), le contrat `FileExporter` étant déjà testé avec un faux.
11. Aucune donnée ne quitte l'appareil par cette fonction (pas de réseau) ; les notes sont exportées telles quelles (avertissement dans la fenêtre : « Le fichier n'est pas chiffré »).

## Hors de cette story

- Export des événements, checklists, réglages (sauvegarde complète : P-04). Envoi par e-mail. Format Excel natif. Impression directe. Enregistrement sur iPhone (ordre 5).

## Décisions (validation automatique)

- D1 — Un seul fichier CSV (les tâches), compatible avec l'import P-07 ; routines, sessions et objectifs sont dans le JSON (évite une archive ZIP et une dépendance).
- D2 — L'export respecte le filtre d'espace global (« filtre partout ») ; la période par défaut est « Tout l'historique ».
- D3 — PNG : rendu canvas 2D d'une mise en page pure (`reportLayout` dans le domaine, polices Fraunces et DM Sans embarquées via `FontFace`) ; pas de capture d'écran du DOM, donc pas de nouvelle dépendance. PDF : écriture d'un PDF minimal contenant l'image JPEG du rendu (`DCTDecode`), environ 80 lignes, sans bibliothèque ; si l'architecte préfère une bibliothèque, licence à valider dans docs/licences.md.
- D4 — Contrat `src/platform/files` : `FileExporter.save({ suggestedName, mime, data }) → { saved, path? }`, `FilePicker.pickText({ accept }) → { name, text } | null`, avec implémentations Tauri (plugins dialog et fs limités au chemin choisi), navigateur (tests) et faux. Il sert à H-03, P-04 (copie d'une sauvegarde), P-07.

## Ordre des sous-tâches

1. platform : `FileExporter` / `FilePicker` et leurs implémentations ; capabilities Tauri minimales (desktop-tauri).
2. domain-logic : `tasksToCsv`, `historyToJson`, `reportLayout` ; tests (échappements, BOM, accents, filtre).
3. stats-history : lecture par blocs dans `StatsRepository`, rendu PNG / PDF, fenêtre d'export ; i18n.
4. e2e (faux `FileExporter`) ; qa-test, code-reviewer.

### Corrections après revue, audit et QA (2026-10-04)

- Injection de formule : `-` et `－` ajoutés aux débuts neutralisés (sauf nombre négatif pur), ainsi que `\n` et `＝ ＋ ＠` ; l'import P-07 retirera l'apostrophe.
- Enregistrement par Rust (`export_save_file`, `reveal_exported_file`) : plus de plugin fs ni dialog côté WebView, plus de `fs:allow-remove` ; chemins réseau refusés ; fermer pendant l'export abandonne la suite ; « Afficher dans le dossier » refusé donne un message.
- Limite connue : lecture par blocs à coût quadratique (tri sur une expression non indexée), voir docs/dettes.md ; `ExportDialog` à factoriser avec les autres fenêtres (docs/dettes.md).
