## Critères testables

1. **Étant donné** 3 items cochés sur 6, **quand** je touche « Effacer les cochés », **alors** une confirmation « Effacer 3 éléments cochés ? » (Effacer / Annuler) s'ouvre ; Annuler ne change rien.
2. **Quand** je confirme, **alors** les 3 items disparaissent, « 0 / 3 », et un message « 3 éléments effacés » avec « Annuler » reste 5 s ; Annuler (ou Ctrl+Z) les restaure à leur place.
3. **Étant donné** aucun item coché, **alors** « Effacer les cochés » est inactif (`aria-disabled`).
4. **Quand** je touche « Tout décocher », **alors** tous les items se décochent d'un coup (sans confirmation), « 0 / 6 », message « Annuler » 5 s ; inactif si rien n'est coché.
5. **Quand** je touche « Réorganiser », **alors** les poignées apparaissent (iPhone) avec un « − » par item et le bouton devient « Terminer » ; PC : poignées toujours visibles, le bouton ajoute les « − ».
6. **Quand** je glisse une poignée (ou Alt+↑ / Alt+↓ sur la ligne sélectionnée), **alors** l'item change de place et l'ordre est conservé après redémarrage ; annulable (`reorder`).
7. **Quand** je touche « − » sur un item, **alors** il est supprimé (message « Annuler » 5 s).
8. Toutes les suppressions sont logiques (`deleted_at`) pour la synchro ; les écritures d'un lot sont une transaction.
9. Boutons atteignables au clavier ; focus restitué après la boîte de confirmation.

## Hors de cette story

- Réorganiser les checklists entre elles ; glisser entre checklists.

## Décisions (validation automatique)

- D1 — « Tout décocher » sans confirmation mais annulable (le PRD ne demande la confirmation que pour l'effacement).
- D2 — Réorganiser : sur PC les poignées restent visibles (maquette), le bouton active aussi les « − » ; sur iPhone, mode explicite (comme A-05).
- D3 — Réutilise `useRowReorder` / `setSortOrders` : aucune nouvelle primitive.
