## ADR requis avant le code

**ADR 0013, section 2 « Verrouillage biométrique », par l'architecte** (même document que A-07 et I-02). Contenu attendu :
1. Plugin officiel `tauri-plugin-biometric` (version épinglée, source Swift relue ; LAContext avec repli sur le code de l'iPhone, `allowDeviceCredential`), `cfg(target_os = "ios")` seulement, capability `biometric-ios.json` à liste exacte (`status`, `authenticate`), entrée `biometric` (story I-03) dans le contrat Info.plist avec `NSFaceIDUsageDescription` en français ; port `src/platform/biometric` (faux, vide, Tauri ; un seul fichier nomme le plugin).
2. Politique de verrouillage (domaine pur, M0) : verrouillé au lancement à froid ; verrouillé au retour au premier plan après **30 secondes** en arrière-plan (délai fixe, recommandation) ; excursions voulues par l'app (sélecteur de dossier, caméra du scan, fenêtre d'autorisation, SideStore) marquées « excursion » et sans reverrouillage immédiat ; échec fermé : toute erreur laisse l'app verrouillée avec un message, jamais déverrouillée.
3. Frontière de sécurité : le verrou couvre l'interface (aucun contenu rendu ni lisible par VoiceOver, aperçu du sélecteur d'apps masqué) ; il ne couvre pas la base ni la synchro ni les notifications (celles-ci continuent en arrière-plan ; le texte des notifications sur l'écran verrouillé suit le réglage iOS, decisions.md 2026-10-08) ; l'option est locale (jamais synchronisée), activable seulement après une authentification réussie.

## Décisions recommandées (à valider par Ali)

- D1 — **Délai de reverrouillage** : 30 secondes fixes (pas de réglage de délai en v1).
- D2 — **Option** : Réglages > Sécurité > « Verrouiller avec Face ID », **désactivée par défaut**, visible sur iPhone seulement ; nom du réglage : « Face ID » si l'appareil a Face ID, sinon le texte générique « Biométrie » (Touch ID), repli « code de l'iPhone » dans tous les cas.
- D3 — **Pas de contournement** : aucune récupération sans authentification ; si la biométrie est supprimée de l'iPhone, le code de l'iPhone suffit ; si aucun code n'est défini sur l'iPhone, l'option ne peut pas être activée (raison affichée) et un verrou déjà actif se désactive avec message visible (voir critère 9).
- D4 — **Aperçu des notifications** : l'écran Sécurité dit en une ligne que Face ID protège l'app, pas le texte des notifications affichées par iOS (à régler dans Réglages iOS > Notifications).

## Critères testables sans Mac

Légende : **[U]** Vitest, **[S]** contrôle statique, **[R]** `cargo test`, **[E]** Playwright projet `iphone` (biométrie injectée en développement seulement, `__ctBiometric`), **[CI]** `build-ios.yml`.

### Politique et réglage (M0, domaine)

1. **[U]** **Étant donné** la politique pure `shouldLock({ enabled, now, backgroundedAt, excursion, state })`, **alors** : désactivé, jamais ; lancement à froid activé, toujours ; retour après 29 s : non ; après 30 s : oui ; excursion déclarée : non, et l'excursion expire après 5 minutes (jamais de contournement durable) ; horloge qui recule : verrouille. Table de cas exhaustive.
2. **[U]** **Alors** le réglage `security.appLock` est de portée `local` (absent du catalogue de synchro et des déclencheurs de capture, test `syncCatalogue.test.ts` inchangé), valeur par défaut faux, valeur illisible lue comme **vrai** (échec fermé) avec journal `setting-unreadable`.

### Plugin et cohérence

3. **[S]** **Alors** : seul `src/platform/biometric/tauriBiometric.ts` nomme `plugin:biometric` ; `Cargo.toml` ne le déclare que sous `cfg(target_os = "ios")` ; `lib.rs` l'enregistre sous le même `cfg` ; la capability iOS a la liste exacte (test `config.rs`) et aucune capability Windows n'accorde `biometric:` ; le résolveur rend l'implémentation « indisponible » sur PC et dans le navigateur.
4. **[CI]** **Alors** `build-ios.yml` lancé sur la branche du lot est vert ; l'étape « Contrat des permissions Info.plist » exige `NSFaceIDUsageDescription` non vide, dont le texte français figure dans `src-tauri/Info.ios.plist` (« CircleTasks utilise Face ID pour garder vos tâches privées. ») ; le test Vitest du contrat est mis à jour.

### Comportement

5. **[U]** **Étant donné** le faux plugin avec biométrie disponible, **quand** j'active l'option dans Réglages > Sécurité, **alors** une authentification est demandée d'abord (raison : « Activer le verrouillage de CircleTasks ») ; réussite : l'option s'active ; échec ou annulation : l'option reste désactivée avec « Le verrouillage n'a pas été activé » ; désactiver demande aussi une authentification.
6. **[U]** **Étant donné** l'option active, **quand** l'app démarre ou revient après 30 s, **alors** un écran opaque « CircleTasks est verrouillée » (nom de l'app, icône, bouton « Déverrouiller ») s'affiche **avant** tout contenu, l'authentification est lancée d'elle-même une fois, puis sur « Déverrouiller » ; réussite : l'écran se retire et l'état précédent (écran, saisie en cours) est retrouvé ; échec ou annulation : l'écran reste, message « Déverrouillage annulé » ou « Déverrouillage impossible ({code}) », nouvel essai possible sans limite côté app (limites et repli code gérés par iOS).
7. **[U]** **Alors** tant que verrouillée : le contenu de l'application n'est pas rendu (aucune ligne de tâche dans le DOM, `inert` et `aria-hidden` sur la racine de l'app, l'écran de verrou est le seul contenu lisible par VoiceOver), les raccourcis et le bouton + ne répondent pas ; la base, la synchro, la replanification des notifications et le passage Rappels Apple **continuent** (tests : un `onRemoteChanges` simulé pendant le verrou replanifie).
8. **[U]** **Alors** au passage en arrière-plan (`visibilitychange` masqué, puis aussi `pagehide`) un **cache de confidentialité** opaque est posé aussitôt pour l'aperçu du sélecteur d'apps, **avant** tout autre traitement, même si le délai de 30 s n'est pas écoulé ; il est retiré au retour sans authentification si le délai n'est pas écoulé.
9. **Aucun échec silencieux.** **Étant donné** `status` du plugin : biométrie non disponible mais code défini : l'option fonctionne avec le seul code (texte « code de l'iPhone ») ; **aucun code défini** ou plugin absent : option impossible à activer avec la raison affichée ; si le verrou est déjà actif et que l'iPhone n'a plus de code, l'app **reste verrouillée avec « Déverrouillage impossible : aucun code n'est défini sur l'iPhone »** et propose, sans authentification, un seul chemin de sortie : un bouton « Désactiver le verrouillage » qui exige la confirmation « Les données de CircleTasks seront de nouveau lisibles sans protection » (iOS n'ayant plus de protection de l'appareil, le verrou n'ajoute rien) et journalise le fait ; échec du plugin : message persistant avec le code et « Réessayer », bandeau jamais nécessaire car l'écran de verrou est le seul écran.
10. **[U]** **Alors** les actions de notification (N-03) reçues pendant le verrou sont inscrites dans la file durable (aucune perte) et appliquées au passage suivant, déverrouillé ou non (opération idempotente de l'ADR 0012 N1.4) ; l'ouverture depuis une notification demande le déverrouillage comme toute ouverture ; les excursions de Y-IOS (sélecteur de dossier, scan du QR, confirmations natives) et de K-05 (autorisation des Rappels) déclarent une excursion.
11. **[U]** **Alors** accessibilité : le bouton « Déverrouiller » est nommé, le message d'échec est annoncé (`role="alert"`), contraste AA clair et sombre, texte agrandi jusqu'à 200 %.
12. **[E]** Projet `iphone`, biométrie injectée : activation avec authentification, verrou au rechargement de la page, déverrouillage, échec puis réussite, retour après 31 s simulées (horloge injectée) ; aucun contenu dans le DOM verrouillé ; projet `pc` : section Sécurité absente, aucun verrou.

## Critères seulement vérifiables sur l'appareil (reportés dans `_checklist-ordre-5.md`)

- A1. Fenêtre Face ID réelle à l'activation et au lancement ; échec volontaire (masque) : bascule vers le code de l'iPhone ; annulation : écran de verrou conservé.
- A2. **Sélecteur d'apps** : l'aperçu de l'app ne montre aucune tâche (cache posé à temps ; sinon l'ADR doit retenir un cache natif).
- A3. Retour avant 30 s (pas de demande) et après 30 s (demande) ; aller à l'appareil photo (scan du QR de Y-IOS-02) et revenir : pas de reverrouillage immédiat.
- A4. Verrou actif et synchro en arrière-plan : une tâche créée sur le PC arrive sur l'iPhone pendant le verrou, la notification sonne.
- A5. **Mise à jour par SideStore** avec le verrou actif : l'app reste verrouillée, l'option conservée ; réinstallation propre : option désactivée (réglage local perdu avec l'app supprimée).
- A6. Réglage iOS « Face ID pour CircleTasks » refusé : le repli sur le code est proposé, message clair.
- A7. Texte de la demande Face ID conforme au Info.plist, sans faute.
