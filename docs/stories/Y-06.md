### Associer l'iPhone (instance `show`)

4. **Étant donné** une synchro configurée avec clé, **quand** j'ouvre Réglages > Synchronisation > Détails, **alors** l'emplacement « appairage » affiche le bouton « Associer l'iPhone » ; **quand** je le touche, `main` appelle `openPairing('show')` : la confirmation native s'ouvre (« Annuler » par défaut, Y-08) ; refus ou fermeture : message « Affichage annulé », aucune fenêtre ; `rate-limited` : « Trop de demandes : réessayez dans 10 minutes » ; `consent-denied` (application pas au premier plan) : « Revenez dans l'application et réessayez » ; `io` (page absente) : « Installation incomplète : réinstallez l'application » ; aucune de ces erreurs n'ouvre de boîte bloquante (§2.1, §10.3).
5. **Alors** la fenêtre `pairing` (PC-Appairage.html) appelle `pairingPayload()` **une fois**, puis affiche le titre, l'avertissement « Ce code transmet la clé… », les trois lignes d'instruction, le **QR** (`qrcode-generator` chargé à la demande, `role="img"` avec un nom accessible **sans** la clé), la **clé de secours** groupée (`CT1-XXXXX-XXXXX-…`), « En attente de l'iPhone… », « Code valable 5 minutes · Nouveau code », le texte « Ce code n'apparaît pas dans les captures d'écran », « Imprimer la clé de secours » et « Annuler » ; **pas de bouton « Copier »** (§10.3).
6. **Alors** le compte à rebours part de `expiresAt` (horloge injectée) ; à l'échéance, QR et clé sont **effacés de l'état avant** la destruction de la fenêtre (Rust la détruit) ; « Nouveau code » appelle `pairingPayload({ renew: true })` : nouvelle confirmation native dont la fenêtre propriétaire est `pairing`, nouveau code, minuteur remis à 5 minutes ; **refus** ou `rate-limited` : l'ancien code reste affiché jusqu'à son échéance et un message le dit (D7) (§2.1, §10.3, audit B4).
7. **Quand** je touche « Imprimer la clé de secours », **alors** l'avertissement « Une imprimante ou un fichier PDF peut garder une copie de la clé : rangez la feuille comme un mot de passe » s'affiche **avant** l'impression (deuxième touche « Imprimer »), puis `window.print()` ; la feuille imprimée ne contient que la clé de secours (pas de QR, `@media print`) (D3) (§10.3).
8. **Alors** « Annuler », Échap, la croix de la barre de titre, la réduction ou la fermeture de `main` et l'expiration **détruisent** la fenêtre (jamais un simple masquage) et remettent l'état à `null` ; `sync_pairing_close` ne vise que la fenêtre appelante (§2.1).
9. **Étant donné** la fenêtre ouverte, **alors** `main` rescanne le dossier toutes les 10 s tant qu'elle existe ; **quand** un appareil dont le `state.ctx` authentifié porte `pairedBy` = l'identifiant de ce PC apparaît, **alors** Rust **détruit** la fenêtre et émet `sync-paired` vers `main` (sans clé) ; `main` rafraîchit la ligne et la liste APPAREILS, lance un cycle (`syncNow`) et affiche « iPhone associé » ; testé par `cargo test` (scan simulé par un `SyncFs` de test : arrivée, appareil sans `pairedBy`, `pairedBy` d'un autre PC, instance en mode `import`) et par Vitest (écoute de `sync-paired` via `DesktopPlatform.onSyncPaired`, comme `onTraySyncNow`) (§10.3).

### Associer cet appareil (instance `import`, clé de secours)

10. **Étant donné** un dossier lié sur un appareil **sans clé** (état `needs-pairing`, Y-01 critère 10), **alors** la ligne de Réglages affiche en plus de « Ce dossier contient déjà des données chiffrées : associez cet appareil » le bouton « Associer cet appareil » ; il ouvre `openPairing('import')` (aucune confirmation à l'ouverture) ; la fenêtre `pairing` affiche `RecoveryKeyEntry` : un champ `autocomplete="off"`, `spellcheck={false}`, `autocapitalize="characters"`, « Associer » et « Annuler » ; **l'interface ne décode ni ne reformate** la saisie (décodage et contrôle en Rust) ; le champ est **vidé après l'envoi** ; sans dossier lié, « Associer » n'est pas proposé (dossier d'abord, clé ensuite) (§2.1, §10.3, decisions.md « Ordre de l'association »).
11. **Alors** chaque code d'erreur de `import` a un texte français sans recopie de la saisie : `invalid-pairing` « Cette clé de secours n'est pas valide : vérifiez la saisie » ; `key-mismatch` « Cette clé ne correspond pas aux données du dossier » (rien n'est enregistré) ; `cloud-pending` « Le dossier ne contient pas encore les données du PC » ; `pairing-expired` ; `consent-denied` ; `rate-limited` (5 imports par 10 minutes) ; `not-configured` ; `wrong-window` ; une saisie erronée se corrige dans le même champ ; remplacer une **autre** clé passe par la confirmation native de Rust (aucune boîte à nous) (§10.3, §11.1).
12. **Alors** la fenêtre d'import affiche « Cette fenêtre se fermera dans N min » (minuterie locale de 5 minutes, D4) et se ferme vide à l'échéance ; **à la réussite**, Rust émet `sync-paired`, détruit la fenêtre, `main` repasse la ligne de Réglages de `needs-pairing` à l'état normal et lance un cycle (§2.1, Y-08 « Information »).
