# T-10 — Je modifie ou arrête une récurrence

Module : M1 Tâches · Ordre de construction : 1 (Socle) · Agent : **tasks-planning** (règles : domain-logic) · Statut : à faire

## Rappel PRD (section 4, M1)

| ID | User story | Critères d'acceptation |
| --- | --- | --- |
| T-10 | Je modifie ou arrête une récurrence | Choix « cette occurrence » ou « toutes les suivantes » ; fin à une date ou après N occurrences |

## Références visuelles

- Ajout.html : lien « Autre : tous les N jours, Nᵉ jour du mois, date de fin… ».
- Detail.html / PC-Aujourdhui.html : ligne « Répétition ». Aucune maquette du choix « cette occurrence / toutes les suivantes » (boîte de dialogue à styliser par ui-design-system).

## Critères testables

1. **Étant donné** une occurrence récurrente, **quand** je modifie son titre, sa note, son icône, son heure, son espace ou son projet et valide, **alors** une question s'affiche : « Cette occurrence » / « Toutes les suivantes » / « Annuler ».
2. **Quand** je choisis « Cette occurrence », **alors** seule la tâche courante change ; l'occurrence suivante sera générée avec les valeurs de la série.
3. **Quand** je choisis « Toutes les suivantes », **alors** la tâche courante change et la série enregistre les nouvelles valeurs (les occurrences futures les reprennent) ; les occurrences passées et terminées restent inchangées.
4. **Étant donné** une modification de la règle (fréquence, jours) ou de la date, **alors** seul « Toutes les suivantes » est proposé pour la règle ; un changement de date seul sur l'occurrence propose les deux choix.
5. **Étant donné** « Autre », **quand** je fixe « Fin le 31 déc. 2026 », **alors** aucune occurrence n'est créée après cette date ; **quand** je fixe « Après 6 occurrences », **alors** la 6ᵉ terminée ou passée ne crée pas de 7ᵉ (comptage par `seriesIndex`, première = 1ʳᵉ occurrence).
6. **Étant donné** une occurrence, **quand** je choisis « Arrêter la répétition », **alors** la tâche courante devient une tâche simple et aucune occurrence suivante n'est créée ; le détail affiche « Une fois ».
7. **Étant donné** une occurrence, **quand** je la supprime (T-08), **alors** « Cette occurrence » supprime la tâche et génère la suivante ; « Toutes les suivantes » supprime la tâche et arrête la série.
8. **Alors** chaque choix est annulable (message 5 s, Ctrl+Z) et le détail affiche la fin (« Mensuelle, le 23, jusqu'au 31 déc. 2026 » / « …, 6 fois »).
9. **Étant donné** une fin déjà dépassée lors de la saisie, **alors** l'enregistrement est refusé avec un message clair.

## Hors de cette story

- Création des règles : T-09. Routines : M4.

## Ordre des sous-tâches

1. domain-logic : application d'un `TaskPatch` à l'occurrence ou à la série ; fin `until` / `count` dans `nextOccurrence` ; tests.
2. Repository `RecurrenceRepository.update` / `end`.
3. ui-design-system : dialogue de choix à 2 options + Annuler.
4. Cas d'usage annulables ; UI détail (ligne Répétition modifiable), écran « Autre ».
5. Tests et e2e (parcours clé 5) ; qa-test, code-reviewer, vérification product-owner.

## Écarts

- Le modèle ne stockant que l'occurrence courante, « toutes les suivantes » s'applique à la série (`recurrence` + valeurs de référence) : l'architecte doit préciser où sont gardées les valeurs de série (titre, note…) — aujourd'hui portées par l'occurrence courante. Signalé à architect, sans incidence fonctionnelle.

## Note d'implémentation

- L'édition du titre, de l'heure, de l'espace et du projet dans la fiche détail relève d'A-08 : le cas d'usage est prêt (`createSeriesUseCases(...).updateOccurrence`, choix « cette occurrence / toutes les suivantes » par `scopeChoicesForEdit`) ; seuls la note et l'icône sont éditables dans la fiche aujourd'hui. Le report (« Reporter », Ctrl+D) d'une occurrence récurrente pose la même question (critère 4).
