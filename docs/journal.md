## 2026-10-27 — Q-05 instable en CI : Entrée ignorée tant que le bloc des options n'est pas chargé (cause trouvée, correctif à planifier)

Constat : run 40565118802 (branche `ci-webkit-01-cache`, qui ne touche ni `src/` ni les tests), job `e2e iphone (3/4)`, test `Q-05.spec.ts:16` thème sombre : après « Acheter du pain #perso » puis Entrée, la feuille « Nouvelle tâche » reste ouverte 5 s ; l'instantané d'erreur montre le champ Titre encore rempli, le bouton « Ajouter la tâche » présent et actif, aucune tâche créée. Un échec sur 14 runs verts de ce job le 27 octobre. Cause lue dans le code : depuis UI-REFONTE-01 (#86), `TaskCreateSheet` rend le bouton de soumission `disabled` tant que `submitLabel === null`, et ce libellé n'arrive que par `onReady` du bloc à la demande `TaskCreateOptions` (import dynamique après le premier affichage, `startTransition`). Un bouton de soumission désactivé bloque la soumission implicite du formulaire : l'Entrée tapée avant l'arrivée du bloc ne fait rien, sans retour (le titre est valide, donc pas de tremblement non plus). La trace Playwright du test le confirme : à l'ouverture de la feuille (158,6 s) le bouton affiche « Chargement… » et porte `disabled` ; l'Entrée est envoyée à 159,2 s ; « Ajouter la tâche » n'apparaît dans un instantané qu'à 159,3 s. Sur un runner chargé, le bloc arrive après la frappe de Playwright ; sur l'iPhone, une saisie rapide juste après l'ouverture peut rencontrer le même silence. Régression du critère 9 de Q-05 (« Entrée crée la tâche »). Aucun test ni délai modifié ; le run suivant de la branche (0ebfdfc5, docs seulement) sert de contrôle, aucune relance. Correctif proposé (story Q-05-FIX-01, ligne au backlog) : l'Entrée sur un titre valide appelle `submit()` directement depuis `handleTitleKeyDown` (il attend déjà `parseNowLoaded()`), le bouton ne dépend plus du libellé du bloc à la demande pour accepter la soumission ; test rouge avant : Entrée avant l'arrivée du bloc crée la tâche.
